# 终端演示录制与回放

优先采用“准备命令 → 真实执行并录制 → 调整回放节奏 → 导出视频”的流程。第一次执行仍需等操作完成；后续回放只展示已记录内容，不再执行部署、推理或其他命令。

按用户的默认偏好，成片直接使用真实终端背景，保留交互式 shell 的提示符、输入命令和输出。画面不叠加标题、页眉、标签等文字。用户要求字幕时，只添加说明字幕。

## 选择实现方式

- **已有运行环境、希望消除等待和重复操作**：优先 asciinema，记录一次真实会话，保存 `.cast`，按需回放、转成 MP4 或嵌入网页。
- **希望连第一次输入也自动化**：用 Expect/pexpect 等 PTY 自动化发送准备好的命令，并由 asciinema 捕获会话。等待提示符或明确的完成标记，设置与操作相符的超时，失败时停止；不要用大量固定 Sleep 掩盖失败。
- **希望用文本编排打字、窗口样式和停顿并生成视频**：可用 VHS `.tape`。VHS 每次渲染通常会真实执行命令，不能当作已录结果的离线回放。需要消除重复远程操作时仍选 `.cast` 回放。

读取本机工具的 `--help` 确认版本和选项。必要时查看 [asciinema 文档](https://docs.asciinema.org/manual/cli/quick-start/)、[agg 文档](https://docs.asciinema.org/manual/agg/usage/) 或 [VHS](https://github.com/charmbracelet/vhs)。不要假定工具已安装；只有需要使用时再准备依赖。

## 准备一次可验证的真实录制

根据用户目标拟定精简命令清单及每段成功标志。复用用户已有环境与脚本，不将某次演示的节点名、云项目、镜像、模型或凭据写成通用默认值。

- 选定终端大小、字号、主题，录制和回放保持相同或兼容的行列数。需要左右分屏时，可在 tmux 等终端复用器内录制。
- 可以预拉镜像、准备缓存、预热推理，但说明这些准备条件，不把预热结果描述成冷启动性能。
- 命令和实际输出应可辨认。用 PTY 自动输入时，让真实 shell 回显命令；普通批处理脚本不一定展示命令，不要只靠伪造提示符或粘贴历史输出模拟真实执行。
- 录制功能验证前确定可观察的结果，例如部署就绪、计算结果、HTTP 状态及实际推理内容。不要将 Running 一概视为服务可用。
- 制作演示不额外授权云资源创建、服务中断、清理已有工作负载或公开上传。只在当前请求允许的环境与动作范围内执行；不为重复渲染而反复修改远程状态。

### 需要展示现场状态变化时

- 用户要看操作如何触发状态变化时，从触发前开录。在画面里保留基线、实际触发命令及其输出。需要帮助观众理解时，可以在命令前用简短的 shell 注释交代目的。
- 关键状态可能很快消失时，在触发前启动 watch 或持续采样，保留同一轮的事件和时间。按演示目标选择验证方式，例如确认故障恢复后，向服务发送实际请求并检查响应。剪辑时用原始录制和同轮记录核对事件顺序。
- 用历史日志或事后查询说明状态变化时，在交付说明里注明来源和采集时间。

## 录制与压缩等待

常用命令（使用前确认本机版本）：

```bash
# 开始录制，在子 shell 中执行演示；exit 或 Ctrl+D 结束
asciinema rec demo.cast

# 远程演示：打开带 PTY 的交互式 SSH 会话，等远端提示符出现后输入命令
asciinema rec -c 'ssh -t user@host' remote.cast

# 回放：把每段无输出间隔限制为最多 2 秒
asciinema play --idle-time-limit 2 demo.cast

# 按需加速，不要让命令和结果快到无法阅读
asciinema play --idle-time-limit 2 --speed 1.5 demo.cast
```

`--idle-time-limit` 只压缩没有终端输出的间隔：连续进度条、轮询日志、反复的 `PodInitializing` 不会被自动跳过。优先用适当的状态等待命令，例如 `kubectl rollout status ... --timeout=900s`，完成后再显示摘要；不要持续轮询尚不能读取的主容器日志。

等待命令也可能输出很多内容，不能承诺一定压缩成两秒。仍有冗长片段时，保留原始 `.cast`，另外生成经剪辑或加速的演示版本，保留关键状态转换和最终证据。修改 asciicast 时间轴前先辨认格式版本及其时间语义；不要把不同版本都当作相同的绝对时间 JSON 行。

保留真实失败与修正的事实；需要简洁成片时可重录成功流程或剪辑，但不得编造成功输出。在交付说明中注明等待已压缩或加速；用户要求字幕时可在相应字幕中注明；不根据剪辑后时长声称真实性能。

## 形成可交付视频

`.cast` 是终端记录，不是 MP4。按用户需要选择：

- 直接终端回放或网页播放器：交付 `.cast` 和回放参数，通常不需要转视频。
- MP4：可录屏捕获压缩后的回放，或使用 agg 渲染后通过 FFmpeg 转换。agg 的常见输出是 GIF；不要把 GIF 改扩展名当成 MP4。复杂终端画面要检查调色板转换是否损失清晰度。
- VHS 编排输出：确认输出格式受当前版本支持，并记住渲染可能重新执行脚本。

如果用户要求字幕，先检查是否有音轨。有讲解时按音轨校对；无音轨时根据实际画面写说明字幕，不称为语音转写。交付可编辑 SRT；如烧录字幕，应避免遮挡命令和结果，可在底部加字幕留白。用户只要求字幕时不要额外改变视频节奏。

导出后用 ffprobe 检查格式、分辨率和时长，抽看开头、状态转换、结果和结尾，确认中文字体、字幕同步、输出可读性及播放结束正常。保留原始素材；只报告实际生成和验证过的产物。

最终交付用户所需格式及可复用的 `.cast`、自动输入脚本或 `.tape`（若有），有字幕则附 SRT。说明如何回放、等待是否压缩及录制依赖；文件交付到用户指定目录，未指定时采用独立输出目录，不混入业务仓库或提交测试产物。公开发布或上传需要当前任务的明确授权。
